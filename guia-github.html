Editar els apunts i publicar-los a GitHub Pages

Descarrega el web preparat per a GitHub Pages · Torna al mòdul

1. Quina eina fa què?

EinaFunció
Editor, com Visual Studio CodeModificar el text i els fitxers del web.
GitHub DesktopVeure els canvis, guardar-ne versions i enviar-les a GitHub.
GitHubDesar el repositori, és a dir, els fitxers i el seu historial.
GitHub PagesPublicar aquests fitxers com un web accessible per l’alumnat.

La versió actual del site és HTML, CSS i JavaScript. No té un editor visual incorporat i encara no està convertida a MkDocs/Markdown. Pots editar-la tu, però caldrà modificar HTML. Si més endavant passem a MkDocs, podrem editar els apunts en Markdown; això requereix una adaptació, no s’activa només pujant el web a GitHub.

Google Sites és més fàcil per editar visualment. GitHub Pages encaixa millor si prioritzem conservar aquest disseny, controlar els fitxers i mantenir exemples tècnics. Publicar a GitHub no fa que l’edició sigui automàticament més senzilla.

2. Preparar els fitxers

  1. Descarrega el ZIP amb l’enllaç superior i descomprimeix-lo.
  2. Comprova que hi ha index.html, style.css, app.js, teacher.enc.json, guia-github.html i la configuració .nojekyll. La guia del ZIP no inclou un altre ZIP dins seu.
  3. Conserva una còpia de seguretat. Aquest paquet conté el web per publicar, sense el projecte original de generació ni la contrasenya del professorat.

Zona del professorat: teacher.enc.json conté el material xifrat. Es pot publicar aquest fitxer, però no la contrasenya ni els originals de solucionaris i exàmens. No pugis la carpeta completa del projecte de ChatGPT: conté fonts docents sense xifrar. El ZIP preparat és la còpia que cal utilitzar.

3. Windows o macOS: GitHub Desktop

GitHub Desktop té suport oficial per a Windows i macOS. A Ubuntu, ves directament a l’apartat 5.

  1. Crea un compte a GitHub, si encara no en tens. Instal·la GitHub Desktop i inicia-hi sessió.
  2. A Desktop, selecciona File → New repository. Nom suggerit: smx-seguretat. Tria una carpeta local coneguda i prem Create repository.
  3. Obre la carpeta creada des de Repository → Show in Explorer/Finder. Copia-hi els fitxers descomprimits del pas 2. index.html ha de quedar a l’arrel del repositori, no dins d’una segona carpeta.
  4. Torna a Desktop. A Changes veuràs els fitxers. Escriu a Summary «Primera versió dels apunts M0226» i prem Commit to main. Un commit guarda una versió local; encara no publica el web.
  5. Prem Publish repository. Per seguir aquesta ruta gratuïta, publica un repositori públic: desmarca Keep this code private després de comprovar que només hi ha els fitxers del paquet. Confirma la publicació.
  6. Obre el repositori al navegador amb Repository → View on GitHub i continua al pas 4.

Referència: publicar un projecte amb GitHub Desktop.

4. Activar GitHub Pages

  1. Al repositori del navegador, obre Settings → Pages.
  2. A Build and deployment → Source, selecciona Deploy from a branch.
  3. Selecciona la branca main i la carpeta /(root). Prem Save.
  4. Espera que finalitzi la publicació. Pages mostrarà l’adreça, normalment https://EL-TEU-USUARI.github.io/smx-seguretat/. Substitueix EL-TEU-USUARI pel teu nom real de GitHub; això és només un exemple.
  5. Obre el web i comprova el menú, els vuit temes, el càlcul de SAI i la zona del professorat. La contrasenya és la mateixa que ja tens; no s’ha d’escriure al repositori.
  6. A Moodle, afegeix un recurs URL amb l’adreça de Pages. Els lliuraments i les qualificacions continuen a Moodle.

GitHub Free permet Pages amb repositoris públics. Un repositori privat no converteix necessàriament el web en privat. Font: configurar la publicació de GitHub Pages.

5. Si treballes a Ubuntu: des del navegador

No necessites GitHub Desktop per publicar o corregir els apunts.

  1. A GitHub, crea un New repository anomenat smx-seguretat, públic, amb README inicial.
  2. Entra-hi i prem Add file → Upload files. Arrossega els fitxers descomprimits del paquet, no el ZIP. Confirma amb Commit changes.
  3. Si la configuració .nojekyll no s’ha pujat, crea-la amb Add file → Create new file, utilitza aquest nom i deixa el contingut buit. Guarda el canvi.
  4. Activa Pages seguint l’apartat 4.
  5. Per corregir un text, obre index.html, prem el llapis d’edició, busca el fragment, modifica’l i desa amb Commit changes. Pages tornarà a publicar la versió.

6. Editar un text amb Desktop i un editor

  1. Abans de començar, prem Fetch origin i, si apareix, Pull origin per rebre els darrers canvis.
  2. Obre la carpeta del repositori amb l’editor. Per canviar apunts, edita index.html. Busca una frase o un identificador com id="acl". El paquet està distribuït en línies per facilitar-ne la cerca.
  3. Canvia el text entre les etiquetes. Per exemple, a <p>Text de l’explicació.</p>, modifica només el text. No eliminis els identificadors: el menú els utilitza.
  4. Guarda el fitxer. Per comprovar també la zona privada, serveix la carpeta per HTTP local, per exemple amb python -m http.server 8000 si tens Python instal·lat, i obre http://localhost:8000. Obrir index.html amb doble clic pot funcionar per als apunts, però la càrrega del fitxer xifrat pot fallar.
  5. A Desktop revisa les diferències, escriu «Aclareixo els permisos de grup» i prem Commit to main. Després prem Push origin per enviar el canvi.
  6. Quan Pages acabi, comprova el resultat al web públic. Si no canvia, revisa Actions i actualitza la pàgina sense memòria cau.

Afegir una imatge: desa-la, per exemple, a imatges/rack.jpg i insereix <img src="imatges/rack.jpg" alt="Rack amb equips i cablejat etiquetat">. Utilitza una imatge pròpia o amb permís d’ús i conserva’n l’atribució.

Editar solucionaris: el fitxer xifrat no s’edita com a text. Cal modificar l’original privat i tornar-lo a xifrar amb el procediment de generació. Aquest ZIP serveix per publicar-lo i editar els apunts públics; no és un editor visual de la zona privada.

Evitar versions divergents: el site de ChatGPT i el teu repositori GitHub no se sincronitzen automàticament. Un cop migrat, escull el repositori GitHub com a versió principal i comunica els canvis abans de substituir-lo amb una altra exportació.

7. Si alguna cosa falla

ProblemaComprovació
404 a Pagesindex.html a l’arrel, branca correcta, publicació acabada i URL amb el nom del repositori.
No apareixen els canvisHas fet Push, a més de Commit? Revisa Actions i la memòria cau.
No es veu una imatgeFitxer pujat, ruta relativa i majúscules/minúscules exactes.
No s’obre professoratContrasenya correcta, teacher.enc.json pujat i accés per HTTPS o localhost.

Quan la publicació funcioni, comparteix amb l’alumnat l’adreça de Pages, no la de GitHub Desktop ni la pàgina del codi.
